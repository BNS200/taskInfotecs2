# Система обработки строк с распределённой архитектурой
## Предлагаемое решение

### 1. Общая архитектура

Решение базируется на клиент-серверной архитектуре с использованием Producer-Consumer паттерна для многопоточности.

#### **Архитектурные компоненты:**

Динамическая библиотека содержит три функции: processDigits, sumDigits и analyzeSum. Библиотека загружается обеими программами через dlopen/dlsym.

Программа 1 (Клиент) состоит из двух потоков. Поток 1 (InputHandler) выполняет ввод пользователя, валидацию строки (только цифры, не более 64 символов), вызывает Функцию 1 и помещает обработанную строку в SPSC буфер. Поток 2 (DataProcessor) извлекает данные из буфера, выводит их на экран, вызывает Функцию 2 и отправляет результат через Socket Client в Программу 2. Синхронизация потоков осуществляется через семафоры без активного опроса.

Программа №2 (Сервер) запускает SocketServer на порту 8080, принимает подключения от Программы №1, обрабатывает данные через ClientHandler, парсит сообщения через MessageParser и вызывает Функцию 3 (analyzeSum) для анализа. Результат выводится в консоль.

#### **Применённые паттерны проектирования:**

Паттерн Producer-Consumer реализован через InputHandler (Producer) и DataProcessor (Consumer) с использованием SPSC буфера.

#### **Принципы SOLID:**

Принцип единственной ответственности (Single Responsibility) соблюдён, так как каждый класс отвечает за одну задачу: InputHandler – ввод, DataProcessor – обработка, Socket – сеть, MessageParser – парсинг. Принцип разделения интерфейсов (Interface Segregation) реализован через разделение интерфейсов для разных операций (чтение, запись, парсинг).

### 2. Структура классов

#### **Библиотека (lib):**

Функция processDigits выполняет сортировку символов по убыванию и замену чётных цифр на "КВ". Параметры: входная строка, буфер для результата, размер буфера. Возвращаемое значение: void. Алгоритм: сортировка через std::ranges::sort, замена через std::views::transform.

Функция sumDigits вычисляет сумму цифр в строке. Параметры: входная строка. Возвращаемое значение: size_t – сумма цифр. Алгоритм: фильтрация цифр через std::views::filter, суммирование через std::accumulate.

Функция analyzeSum анализирует сумму (> 2 и кратна 32). Параметры: входная строка. Возвращаемое значение: bool. Алгоритм: проверка длины > 2, вызов sumDigits, проверка условий.

#### **Программа №1 (Клиент):**

Класс InputHandler (Поток 1 – Producer) обеспечивает ввод пользователя, валидацию и вызов Функции 1. Основные методы: run() – основной цикл ввода, stop() – остановка обработки. Взаимодействие: передаёт данные в SPSCBuffer.

Класс DataProcessor (Поток 2 – Consumer) выполняет обработку данных из буфера, вызов Функции 2 и отправку в Программу №2. Основные методы: run() – основной цикл обработки, stop() – остановка обработки, sendToProgram2() – отправка данных через сокет. Взаимодействие: получает данные из SPSCBuffer, отправляет через Socket.

Класс SPSCBuffer (Общий буфер) представляет высокопроизводительный кольцевой буфер. Основные методы: push(T&&) – запись (Producer), pop() – чтение (Consumer), interrupt() – прерывание ожидания. Особенности: Lock-free, семафоры, защита от False Sharing.

Класс Socket (Клиентский сокет) обеспечивает TCP-клиент для связи с Программой №2. Основные методы: connect() – подключение к серверу, send() – отправка данных, disconnect() – отключение, ensureConnection() – переподключение при потере связи.

Класс LibraryLoader (Загрузчик библиотеки) выполняет динамическую загрузку lib.so через dlopen/dlsym. Основные методы: load() – загрузка библиотеки, getProcessDigits() – получение Функции 1, getSumDigits() – получение Функции 2, getAnalyzeSum() – получение Функции 3.

#### **Программа №2 (Сервер):**

Класс SocketServer (Серверный сокет) обеспечивает TCP-сервер для приёма подключений. Основные методы: start() – запуск сервера на порту, acceptClient() – принятие клиента, stop() – остановка сервера.

Класс ClientHandler (Обработчик клиента) выполняет обработку данных от Программы №1. Основные методы: process() – основной цикл обработки, processMessage() – обработка одного сообщения, disconnect() – закрытие соединения.

Класс MessageParser (Парсер сообщений) выполняет парсинг сообщений в формате "данные|сумма". Основные методы: parse() – парсинг сообщения, validate() – валидация формата.

#### **Общие компоненты (common):**

LibraryLoader – загрузка динамической библиотеки, общий для обеих программ.
